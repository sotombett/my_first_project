ответы на вопросы 

1. Три основные области:
Рабочая директория (текущее состояние файлов на файловой системе. Изменения здесь либо не отслеживаются, либо помечены как измененные, но еще не добавлены в индекс.)
Индекс или Область подготовленных файлов (промежуточная область, в которой фиксируются изменения, предназначенные для следующего коммита.)
Локальный репозиторий (директория .git, содержащая базу данных объектов, историю коммитов и ссылки.)

2. При выполнении команд:
git add: переносит изменения из рабочей директории в индекс.
git commit: создает новый объект коммита на основе данных из индекса и сохраняет его в локальный репозиторий.
git push: передает объекты коммитов из локального репозитория в удаленный (GitHub) и обновляет соответствующую ветку.

3. Сообщения к коммитам должны быть информативными, потому что это техническая документация проекта. Информативные сообщения помогают понять причину изменений, упрощают отладку и код-ревью.

4. Разница в том, что git add <имя_файла> индексирует только указанный файл, а git add . индексирует все изменения (новые, измененные, удаленные файлы) в текущей директории и поддиректориях.

5. Команда git status отображает состояние рабочей директории и индекса
Варианты вывода:
Untracked files: файлы, не отслеживаемые git.
Changes not staged for commit: измененные/удаленные файлы, не добавленные в индекс.
Changes to be committed: изменения в индексе и готовы к коммиту.
nothing to commit, working tree clean: сообщение об отсутствии изменений, коммитить нечего.

6. Команда git remote add origin URL настраивает соединение с удаленным репозиторием. origin — это стандартный псевдоним для URL удаленного репозитория.

7. Флаг -u устанавливает связь между локальной веткой (main) и удаленной веткой (origin/main). После установки этой связи, последующие команды git push и git pull могут выполняться без указания удаленного репозитория и имени ветки, так как git будет использовать эту настроенную upstream-ветку.

8. Ветка по умолчанию — основная ветка при инициализации репозитория. Ранее использовалось имя master, но современный стандарт — main, так что в моём проекте ветка по умолчанию была main. Это важно, так как локальная и удаленная ветки должны соответствовать друг другу. Если локально создана main, а удаленный репозиторий ожидает master, команда git push будет отклонена.

9. С помощью команды git log. Для каждого коммита отображается: уникальный хеш, имя и email автора, дата и время, сообщение коммита.

10. Команда git commit обрабатывает только те изменения, которые находятся в индексе. Если файлы изменены в рабочей директории, но не добавлены в индекс, они не будут включены в коммит. Если в индексе нет изменений вообще, git commit завершится ошибкой.
